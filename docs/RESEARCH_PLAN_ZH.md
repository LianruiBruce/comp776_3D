## 1. 我们要完成一个什么问题？

用户给模型一张自己的照片，请它生成另一张肖像。输出可能很清楚、很好看，也能被识别器归到这个人，但本人仍然觉得“不太像我”。

这个现象至少包含三个不同的问题：

| 问题 | 例子 | 我们怎样回答 |
|---|---|---|
| 身份能不能认出来？ | 在八个人里，这张图最接近谁？ | 人脸识别指标 |
| 外貌保留得有多准确？ | 脸型、五官组合和表情变化有没有偏离？ | 真实参照、外观诊断和人工判断 |
| 本人觉得像不像？ | “这是一张像我的照片吗？” | 本人评价，不能由陌生人或识别器直接代替 |

**本课题的主问题定为：生成肖像相对于同一个人的真实照片，是否存在稳定的人类 likeness 缺口？当任务只改变表情时，这个缺口是否扩大？**

这里的 *likeness* 指“看起来有多像这个具体的人”，不是漂亮程度，也不是照片真假。

我建议把题目暂定为：

> **真实照片参照下的个性化肖像生成：本人相似度、表情变化与自动身份指标的差距**

这一标题有意不预设结果。如果最后没有发现稳定缺口，研究仍然回答了一个有边界的问题。

### 1.1 研究范围先收窄

第一轮只研究：**一个人、普通写实肖像、输入一张照片、中性表情与微笑两种任务。**

本轮不同时研究多人、换年龄、极端姿态、遮挡、动漫风格、视频、全身一致性，也不同时比较十几个模型。这样才能知道一个结果主要对应什么变化。

数据首先采用有同意的参与者手机人像，并控制距离、光照和拍摄流程。它是**半受控手机人像研究**，不是对所有自然自拍和日常场景的代表性抽样。

### 1.2 我们不会预设这些答案

- ViT 的最后一层擦除了身份；
- 全局向量只能表示“是谁”，局部 token 才表示“长什么样”；
- 多张参考一定比一张好；
- 生成器把所有人变成训练集的平均脸；
- 只要再训练一个 adapter，问题就能解决。

这些都需要证据，不能因为听起来合理就成为论文结论。

## 2. 已有实验做到了哪里？

我们不是从零开始。现有代码已经解决了下载、对齐、特征提取、生成、匿名评分和结果追溯中的很多工程问题。

### 2.1 已完成的证据

| 阶段 | 用新手能理解的话说 | 关键结果 | 可以怎样使用 |
|---|---|---|---|
| E0 / E1 | 检查识别模型不同层是否更容易读出身份 | 简单 token 平均在第 11 层有内部优势，官方最终输出更强 | 支持继续检查“读出方式”，不能宣称发现身份层 |
| E2 | 给每层同样大小、同样训练方式的读出器，再公平比较 | 第 11 层相对第 12 层的内部 TAR 差只有 +0.00067；95% CI [0, 0.002]，预设门槛未通过 | 没有支持该设置下稳定的中间层优势；停止据此训练 block-11 mapper |
| G0 自动评价 | 使用 PhotoMaker V2 生成并检查身份信号 | 192/192 张成功；正常条件八选一 Rank-1 都是 1 | 身份条件确实有效；不能直接说明人类觉得像 |
| G0 连续指标 | 看生成图与真实同身份图库有多接近 | 单图条件 LVFace cosine 约 0.561，真实单图参照约 0.913 | 存在识别空间中的差距；不能把差值换算成人类 likeness |
| H-v2 人评 | 比较多参考条件和通道冲突条件谁更像 | 10 位评分者、96 个唯一配对、480 次判断，已全部完成 | 是完整的探索实验，不需要继续补当前八个身份的票 |

已有结果的正式解释见 [E2 报告](E:/comp776_3D/reports/E2_FEI_FULL_LVFACE_PROBES.md)、[生成报告](E:/comp776_3D/reports/GENERATION_IDENTITY_PILOT.md) 和 [v2 人评协议与结果](E:/comp776_3D/docs/HUMAN_IDENTITY_LIKENESS_V2.md)。

### 2.2 人评的准确结论

| 配对 | 偏好分数 | 95% 置信区间 | 含义 |
|---|---:|---:|---|
| P0：多样四图 vs 单图 | 0.47969 | [0.38698, 0.57083] | 未观察到多样四图的明确优势 |
| P1：多样四图 vs 重复四图 | 0.50573 | [0.43880, 0.58256] | 未观察到参考多样性的明确收益 |
| P3：global-target vs patch-target | 0.38385 | [0.13906, 0.66615] | 方向不确定；69/160 次无法判断，身份间差异很大 |

这些分数包含平票，且按身份等权汇总，不是简单胜率。0.5 是中性点。**区间跨 0.5 表示证据不足以确认方向，不表示两种方法已经被证明等效。**

P0/P1 的平局还可能对应两种完全不同的情形：两边都很像，或者两边都不太像。当前设计无法区分，因为没有把真实照片纳入同一种 likeness 测量。

### 2.3 目前最大的缺口

我们还没有直接测出：

1. 本人如何评价自己的生成图；
2. 真实照片的 likeness 正常波动有多大；
3. 生成图比真实照片低多少；
4. 单独改变表情是否增加了额外损失；
5. 自动指标是否能可靠反映同一个人、同一任务中的人评变化。

**因此下一步应先补齐测量，而不是把 P3 的不确定方向扩大成一场主实验。**

## 3. 做这个课题必须知道的术语

| 术语 | 通俗解释 | 在本课题里的例子 |
|---|---|---|
| Identity / 身份 | 照片里是哪个具体的人 | 张三的十张照片属于一个身份 |
| Reference / 输入参考 | 真正送进生成器的照片 | 一张中性正脸 |
| Gallery / 评价图库 | 评分或计算指标时用的参照照片 | 同一个人的另外三张照片 |
| Held-out | 提前留出、不参与对应的选择或训练 | 图库不送入生成器；确认身份不参与调参 |
| Embedding | 把图像变成一串数值的表示 | 人脸识别器输出的向量 |
| Backbone | 模型中负责主要计算的基础网络 | SDXL 基础生成模型 |
| Adapter / mapper / router | 把额外条件接入大模型的小模块 | 把身份向量转换成生成器可用的条件 |
| VAE | 将图像压缩到潜空间、再解码回图像的组件 | 检查单纯编解码会不会改变脸 |
| Diffusion / 扩散生成 | 从噪声逐步形成图像的过程 | 最后得到一张肖像 |
| Prompt | 对生成内容的文字要求 | “正面、微笑、柔和光照” |
| Seed / 随机种子 | 让随机过程可以重放的编号 | 两次使用相同初始噪声做配对比较 |
| Baseline / 基线 | 已有、可复现的比较对象 | 原版 PhotoMaker V2 |
| Ablation / 消融 | 有控制地删减或改变一个因素 | 固定其它设置，只改变身份注入时段 |
| Pilot / 预试验 | 检查流程、估计变异、改正设计 | 12 个新身份的开发实验 |
| Confirmation / 确认实验 | 设置冻结后，在未使用过的数据上验证 | 另一批身份，只跑预先定好的版本 |
| Confound / 混杂 | 两个因素一起变，无法知道谁造成结果 | 换模型时基础网络和训练数据也一起换了 |
| CI / 置信区间 | 反映估计不确定性的区间 | 区间很宽，说明仍不能排除多种真实效应 |
| Power / 统计功效 | 真有预设大小的效应时，实验发现它的能力 | 用仿真决定需要多少身份 |
| Preregistration / 预注册 | 在看正式结果前写死问题和分析规则 | 先定样本量、主要指标、排除与停止规则 |

最重要的一条：**八个人各生成一百张图，仍然只有八个身份，不能当成八百个独立的人。**

## 4. 文献告诉我们什么，尚未告诉我们什么？

### 4.1 自动识别与人类 likeness 不是同一个优化目标

ArcFace 学习的是身份可分的特征空间；其训练目标并不直接包含本人对生成图的 likeness 评分。这使得“识别指标很高”不能充分保证“人觉得像”。[ArcFace，CVPR 2019](https://openaccess.thecvf.com/content_CVPR_2019/html/Deng_ArcFace_Additive_Angular_Margin_Loss_for_Deep_Face_Recognition_CVPR_2019_paper.html)

F-Bench 在人脸定制任务中报告 ArcFace 与人类身份保真评分的 SRCC 为 0.5062、PLCC 为 0.5572。它支持保留人类终点，但这种人机不完全一致已经是已有研究结果；不能把“指标不等于人评”本身包装成我们的首次发现。[F-Bench，ICCV 2025；数值亦见预印本 Table 2](https://arxiv.org/html/2412.13155v1)

### 4.2 真实照片本身也有好坏 likeness

Jenkins 等发现，同一人的真实照片在 likeness 上有明显变化，熟悉程度影响判断。因此真实照片需要作为一个小分布来比较，不能只挑一张“最像”的照片当绝对真值。[Variability in photos of the same face，2011](https://static1.squarespace.com/static/5e3fac24244c110e4dea7c2a/t/5e43af87685c425c5d5d7c39/1581494168773/JenkinsEtAl2011_Cognition.pdf)

Balas 等进一步发现，熟悉人物的 likeness 不能被“与该人物平均照片的相似度”充分替代。这支持把本人和陌生人判断分开，也提醒我们不能简单把一个人的外貌等同于一个平均模板。[Not the norm，2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10161317/)

### 4.3 全局向量可能有信息，生成器未必用得好

Arc2Face 以 ArcFace 向量作为身份条件，并通过身份到图像的训练产生高相似度人脸。论文的数据规模比较说明，生成端训练覆盖会影响结果。它反驳了“全局向量必然没有足够外貌信息”这种过强说法，但没有证明全局向量足以完全重现本人的感知 likeness。[Arc2Face，ECCV 2024](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/05442.pdf)

### 4.4 复制一张照片与生成同一个人的另一张照片不同

WithAnyone 通过同身份不同照片的配对训练，处理参考复制与可编辑性的冲突；其消融显示配对阶段能够减少复制，并维持目标身份相似度。这使“训练是否教会跨条件身份保持”成为竞争解释，而不只是“缺哪个 token”。[WithAnyone，ICLR 2026；此处正文采用预印本 v1](https://arxiv.org/html/2510.14975v1)

Face2Diffusion 研究身份与表情等信息的解耦，说明表情控制本身就可能与身份保持纠缠。因此本计划先只改变表情。[Face2Diffusion，CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Shiohara_Face2Diffusion_for_Fast_and_Editable_Face_Personalization_CVPR_2024_paper.html)

### 4.5 “局部细节”不是唯一答案

人脸知觉实验支持形状与表面反射信息都参与身份判断，它们的相对作用随条件而变。几何、颜色分布、表情形变都值得检查，但不能据此认定某一网络的 patch 分支对应了全部这些信息。[Russell 等，Vision Research 2007](https://pubmed.ncbi.nlm.nih.gov/17174375/)

近距离自拍还会产生透视比例变化；记录拍摄距离的目的，是减少这一可解释的干扰，而不是假定自拍反映了唯一真实的面部比例。[Nasal Distortion in Short-Distance Photographs，2018](https://pmc.ncbi.nlm.nih.gov/articles/PMC5876805/)

### 4.6 本研究的竞争解释

下表是**待检验假设**，不是文献已替我们证明的结论。

| 可能解释 | 应当看到什么 | 什么结果会削弱它 |
|---|---|---|
| 缺口没有想象中普遍 | 生成与真实参照差很小，且区间足够窄 | 在新身份上出现稳定、明显差距 |
| 自拍没有提供目标表情信息 | 定向补充表情参考，比同数量其它参考更有效 | 补充后没有可重复收益 |
| 生成过程没有充分使用身份条件 | 固定输入，合法改变注入参数能改善 likeness | 参数变化只提高自动分数，或牺牲表情完成度 |
| 自动指标对相关变化不敏感 | 在新身份内，自动改善经常不对应人评改善 | 自动指标能稳定预测未见身份上的人评变化 |
| 基础压缩已损坏外貌 | VAE 编解码本身带来可测的变化 | 重建近似无变化，但身份条件生成有明显缺口 |
| 评价者对人物的经验不同 | 本人和陌生图库评分存在系统差异 | 两组方向一致且差异小 |

我们不承诺一次实验区分所有解释。**先建立现象，再只选择一个可操作的原因继续检验。**

## 5. 总体路线：核心课题与可选扩展

```text
冻结已有结果
    ↓
建立新身份的数据与评分流程
    ↓
小规模开发：确认量表可用、估计方差、完成工程检查
    ↓
冻结正式设置、分析、人数和停止规则
    ↓
新身份确认：真实参照缺口 + 表情变化 + 第二模型复查
    ↓
完成核心研究报告 / 论文
    ↓ 只有存在明确、可干预的问题才继续
一个受控改进 → 又一批未使用身份确认 → 方法扩展
```

核心课题的结束不依赖一个新模型成功。可选扩展使用新的时间和数据预算，不能无限延长原课题。

### 5.1 阶段 A：冻结旧结果，建立项目入口

交付物：当前证据表、本文、旧文件的状态纠正、不会改动历史运行的约定。

已经完成的 FEI 数据、生成图和人评只用于背景说明与工程回归。停止在八身份上重新选 prompt、donor、层或统计规则。CVLFace / Yale B 的层级复制暂时降级：它们可以回答另外的表示问题，但不是当前 likeness 主问题的必要前置步骤。

### 5.2 阶段 B：开发预试验

规划使用 **12 个新身份**。人数是工作量起点，不是功效保证。这批人用于检查流程、修正说明、估计方差；一旦看过结果，就不能进入确认集。

只用当前已验证的 PhotoMaker V2，固定 K=1，两种表情、每格两个 seeds。首先解决：图片能否合理展示、参与者是否理解问题、无法判断为何发生、任务是否实际完成。

预试验可以失败。如果输入照片都不符合要求，或参与者对量表理解不同，应修改流程后重新做独立预试验，不应直接把大量人拉进正式实验。

### 5.3 阶段 C：核心确认实验

身份与阶段 B 完全不重合。规模先以 **40 个身份作为预算示例**，最终由预试验的方差、缺失率和预设最小效应决定，详见第 8 节。

主模型保持 PhotoMaker V2。第二模型优先采用 PuLID v1.1 的 SDXL 版本；它用于检查现象是否只出现在一个系统，不用于证明某个分支是原因。第二模型须先在独立开发材料上通过兼容性与资源检查，不能按“哪种人评结果更符合假设”来选。[PuLID 官方仓库](https://github.com/ToTheBeginning/PuLID)

若 PuLID 在预先分配的两个工作日内无法稳定复现，记录原因，并按预先顺序检查 InstantID；仍不成功则保留单模型课题，并缩小结论范围。不要为了凑表格无限修环境。[InstantID 官方仓库](https://github.com/instantX-research/InstantID)

阶段 C 结束后，这批身份可以用于探索分析，但不能再用来选择改进后宣称是该改进的外部确认。

### 5.4 阶段 D：可选的一次改进

只有阶段 C 发现了有实际意义、测量可靠的缺口，才讨论改进。只选择一个与观察到的问题相符的因素，先做无需训练的受控实验；详见第 10 节。

如果要确认改进，必须再保留一批从未用于选择改进方案的身份。没有这个资源，就将改进结果标为探索性，不追加一轮“伪确认”。

## 6. 每个人需要提供什么？怎样生成？

### 6.1 最小照片分配：每人八张

| 用途 | 数量 | 内容 | 允许进入生成器吗？ |
|---|---:|---|---|
| I：生成输入 | 1 | 清晰中性正脸 | 是，只有这一张 |
| G：评价图库 | 3 | 同一个人的其它照片，按统一模板覆盖外貌 | 否 |
| R0：真实中性候选 | 2 | 另外拍摄的中性照片 | 否 |
| R1：真实微笑候选 | 2 | 与 R0 尽量同距离、姿态、光照的微笑照片 | 否 |

这八张是不同拍摄图像，不能通过复制文件来凑数。图库模板在开发阶段固定，对所有身份一致；不得按“最有利于某方法”选择。可以额外准备备份，但替换只能按提前定义的技术失败规则，发生在生成和评分之前。

尽量分两次短拍摄：一次收输入与图库，另一次收真实候选。R0/R1 在同一次拍摄中交替采集，减少随时间变化的光照和相机位置影响。第二次拍摄不是模型输出对应的唯一真值，只提供独立的真实参照。

记录距离、相机、镜像状态、裁切、美颜或后处理设置。关闭自动美颜，固定可控设置；不能保证设备全部一致时如实记录。对技术合格的照片按预先编号取样，不能事后挑“最好看”或“最像”的样本。

**图库不进入生成器，真实候选不出现在图库里。** 否则评分者可能只是把候选与自己刚看到的同一张图匹配。

### 6.2 主生成矩阵

| 条件 | 输入 | 任务 | 每身份每模型输出 |
|---|---|---|---:|
| T0 | 同一张 I | 普通中性正面肖像 | 2 seeds → 2 张 |
| T1 | 同一张 I | 保持其它要求，只改成微笑 | 2 seeds → 2 张 |

T0/T1 的英文模板只改变表情描述。光照、视角、背景、服装要求和相机描述保持一致，不使用额外的美化性人脸描述。PhotoMaker 所需触发词和其它模型所需输入格式由各自官方实现决定，全部记录。

“保持其它要求”描述的是**指令控制**，不保证实际图像其它属性完全不变。因此必须检查真实输出，不能把这张表直接称为完全隔离表情的因果实验。

同一模型内尽量复用初始 latent，并保存 hash。跨模型即使 seed 数字相同，也不保证随机实现或轨迹相同，不能把它当像素级严格配对；跨模型主要按身份和任务比较。

### 6.3 比较模型时怎样避免不公平

- 主表优先采用同一个可兼容的 SDXL 基础权重、同分辨率和精度；当前 RealVisXL V4 是已验证起点。
- 先测试每个模型是否支持共同设置；不能强行使用不支持的 sampler 或控制接口。
- 共同设置不可行时，分别报告官方推荐配置与差异，降低机制归因强度。
- 某些系统的额外几何输入可能固定输入表情。如果它妨碍微笑任务，应在开发阶段明确处理；不能偷偷给它提供其它模型没有的目标照片。
- 模型结构、训练数据、训练损失仍然不同。因此“模型 B 更像”是系统比较，不能直接写成“局部分支有效”。

### 6.4 VAE 重建只作为辅助检查

开发阶段可把输入 I 进行一次 VAE 编码—解码，并与 I 对照，检查分辨率、颜色或压缩是否明显改变脸。若进行人工量化，需要追加独立条目和预算。

它不能做严格的损失分账：

- 重建好，不代表去噪生成不会改错脸；
- 重建差，不代表全部生成缺口都来自 VAE；
- 不能用“总缺口减 VAE 缺口”计算其它模块的贡献。

原因是两种输出经过的条件与路径不同，误差不一定可加。

## 7. 人评：先回答“像不像”，再问其它问题

### 7.1 主终点选本人评价

原问题是“为什么不像自己”，因此本计划的**主终点是本人对自己照片的 likeness 评分**。每个人只评价自己的候选图。若无法开展本人评分，应在收集前修改问题与标题，将任务改为图库相似度研究，不能在结果出来后把陌生人评价替换成“像自己”。

主问题建议：

> 只考虑脸部外貌，不考虑照片是否好看：这张照片看起来有多像你本人？

采用 1—7 分：1 为“非常不像”，4 为“一般”，7 为“非常像”，另设“无法判断”，不把它当 4 分。

本人当然会认出自己，也可能认出原照片，所以不能声称完全盲化。我们隐藏的是模型名称、生成设置和研究假设；实际来源可能被看出，这一限制必须报告。

### 7.2 陌生人评价是独立的次要终点

陌生评分者看到固定 G 图库和一张候选图，回答：

> 只考虑脸部外貌：这张候选照片与参考图库中的人有多相像？

同样 1—7 分，每张候选规划 5 位不同的陌生评分者。每人评多个身份，各方法与任务在分组中平衡，同一候选不重复交给同一人。

这一终点称为“图库参照下的相似度”，不叫本人认同。默认本人页只显示候选，陌生人页显示 G 图库和候选，因此两组得到的信息和任务并不相同。本人和陌生人得分分开分析；组间差异不能只归因于熟悉程度，原始尺度的均值也不直接等价。

熟人评价可以作为后续第三组，但不是第一轮必须额外招募的负担；记录熟悉程度，避免和本人票混合。

### 7.3 为什么改成单张评分，而不只做 A/B？

旧 A/B 任务适合回答“两个生成条件谁更像”，但不能直接估计两边距离真实参照有多远。新任务把真实和生成候选放在同一套量表上，便于形成身份内差值。

代价是量表有主观尺度差异。因此不比较某个人的 6 分和另一个人的 6 分是否完全相同，而是先比较每个人内部的真实—生成差，再汇总。1—7 分仍是有序量表，均值差作为可解释摘要，同时做有序统计模型的敏感性检查。

后续若比较两种改进方案，可以另外采用盲法 A/B 加平票，但不改写已完成的 v2 数据。

### 7.4 展示与任务分离

- 真实图和生成图使用相同显示区域、背景与缩放规则；保留合理头部轮廓，避免把某组显示得更大或更清晰。
- 不把识别器需要的 112×112 对齐小图直接当成人评主图，也不为“公平”把所有人脸过度模糊。
- 随机排列候选，平衡任务与来源顺序；不向评分者显示自动指标。
- 预试验用独立练习材料解释“像本人”和“好看”的区别，完成后只收流程反馈。
- 正式实验的低 likeness 或“无法判断”不是注意力失败，不能因此删人。技术无效、未完成和响应重复等规则提前冻结。

### 7.5 表情完成度和画质要另外测

微笑任务中，如果输出一直保持中性，可能很像输入，但任务没有完成。因此还要独立记录：

1. 是否实际微笑、姿态是否基本符合要求；
2. 是否存在明显脸部畸形或不可用画质；
3. 是否直接复制参考的表情和构图。

这些问题另开评分页或另一组任务，不和 likeness 混成“总体好不好”。独立人工检查至少由两位评者按固定标准完成，分歧处理规则先定。其工时单独预算。

**主要 likeness 分析不事后删除“不听 prompt”的图。** 可另报告任务完成样本的描述性结果，但那是筛选后的子集，不能替代全体输出结论。

## 8. 统计：怎样避免把噪声当发现？

### 8.1 先定义两个容易理解的量

对某个身份、某个模型：

- R0：两张真实中性候选的平均 likeness；
- R1：两张真实微笑候选的平均 likeness；
- G0：两张生成中性候选的平均 likeness；
- G1：两张生成微笑候选的平均 likeness。

**平均缺口 D：**

```text
D = [(R0 − G0) + (R1 − G1)] / 2
```

D 大于 0，表示该模型生成图的平均 likeness 低于真实参照。D 可以小于 0，真实照片不是数学上界。

**表情条件的额外缺口 E：**

```text
E = (R1 − G1) − (R0 − G0)
```

例如：真实中性 6.0、生成中性 5.5，缺口是 0.5；真实微笑 6.2、生成微笑 4.7，缺口是 1.5。于是 E=1.0，表示微笑条件的差距更大。这是教学假数据，不是项目结果。

E 考虑了真实中性与真实微笑本来就可能有不同 likeness，但仍不能完全消除画质、实际表情强度等混杂；它是有针对性的诊断，不是证明某个内部模块造成了一分损失。

### 8.2 主要分析先写死

默认正式主分析是：**PhotoMaker V2 的本人评分 D**。

E、第二模型的 D/E、陌生人结果和自动指标关系列为预先规定的次要分析。主结果不理想时，不能将其中最好看的一个改名为“主结果”。如果要对一组次要假设作确认性显著性声明，提前固定检验集合并做 Holm 等多重比较校正；否则报告估计与区间，并明确探索性。

本人每个身份通常只有一位，因此本人和身份在此重合。对每个身份先算 D，再按身份汇总均值与区间；不能同时拟合两个独立的“本人随机效应”和“身份随机效应”。

陌生人跨多个身份评分，才存在身份与评分者交叉的依赖。采用与设计一致的混合效应模型，并用同时考虑身份和评分者的重采样作敏感性检查。有序模型、随机效应及模型不收敛时的固定简化顺序，应由统计审阅者在正式评分开始前冻结。[重复测量与随机效应的背景：Barr 等，2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3881361/)

### 8.3 “显著”“重要”“不知道”要分开

先提出 **0.5 个量表分作为最小实际效应的讨论起点**，不是文献给出的通用阈值。开发阶段根据评分锚点、重复性与研究目的确认并冻结，不能看正式结果后调低。

| 结果 | 正确解释 |
|---|---|
| 区间排除 0，但差异很小 | 有方向证据，不一定具有实际意义 |
| 区间整体超过预设实际效应门槛 | 对“足够大的差异”有较强支持 |
| 区间覆盖 0，也包含较大效应 | 不确定，不是证明没差别 |
| 预设等效检验通过 | 在指定容许范围和研究条件下可支持实际等效 |

如需声明“差距小到可忽略”，提前定义等效边界并采用合适检验，而不是以 p>0.05 代替。[Lakens，Equivalence Tests，2017](https://doi.org/10.1177/1948550617697177)

### 8.4 样本量必须根据问题计算

阶段 B 的 12 个身份主要估计 D 的身份间方差、无法判断率与耗时。小预试验的方差也不稳定，不能把它观察到的效应直接当真实效应。

正式前进行模拟：使用预设的最小实际效应，覆盖若干合理方差和缺失率，分别模拟 24、40、60 等身份数下的检出能力与区间宽度。以至少 80% 的规划功效为起点，同时检查精度；最终冻结一个可负担的样本量。[模拟功效分析方法：Green 与 MacLeod，2016](https://besjournals.onlinelibrary.wiley.com/doi/10.1111/2041-210X.12504)

仿真必须匹配最终分析：本人身份差值模型可直接模拟身份；陌生人模型还需模拟评分者、图像与缺失。E 的方差与 D 不同，不能用 D 的功效保证 E。

“真实差异为 0.5 分时，以 80% 功效发现它不同于 0”，与“证明差异至少超过 0.5 分”不是同一个目标。本计划先规划前者并检查区间宽度；若要让区间下限超过实际效应门槛，需要针对高于该门槛的目标真实差异另作设计。

正式冻结时同时写明目标招募身份数、预计可分析比例、最大邀请人数和停止日期。本文 40 身份的预算示例按完整参与计算；正式功效必须考虑缺失后的分析样本，不能默认招募 40 人就必然得到 40 个有效 D。

如果资源只够较小规模，就缩小声明为探索性研究或强调估计精度。不能生成更多同身份图像，假装补足了新身份。

### 8.5 无法判断、生成失败和退出

- 保存全部预期生成单元；无人脸、多脸、对齐失败和生成失败都要有状态，不重新抽 seed 直到成功。
- 有图像但识别器检测失败，仍可能可以供人判断；人评与自动指标的可用性分开记录。
- “无法判断”是缺失的 likeness 评价，不自动记为最低分、中间分或否定票。
- 主报告同时列出各条件有效数、缺失数，以及按预设规则计算的可判断样本估计。
- 对已有图像但缺失的 likeness 评分，使用 1—7 分范围做最有利/最不利界限或预注册的缺失敏感性分析；若结论依赖如何填补，应明确其脆弱性。生成失败根本没有图像，另计生成可用性，不能用量表补值声称测出了它的 likeness。
- 若某身份不足以计算预设差值，保留在总身份账本中并报告原因；不按结果好坏决定是否补人。
- 技术补采、退出、最大邀请数与停止时间提前固定。知情同意中的撤回约定优先，撤回导致的可复现限制记录在案。

**拟定的可计算规则：**某个身份的 R0、R1、G0、G1 四格各至少有一张候选获得有效本人评分，才计算该模型的 D/E；每格先对有效候选等权平均，再保持两条件等权。同时报告每格数量和四格共八张候选全部有评分的敏感性结果。这一规则在开发结束后冻结，不能按正式效果修改。

该估计针对可评价身份与可判断候选，不能自动代表所有招募者和输出。缺失界限应覆盖全部仍同意纳入分析、且存在相应候选图的身份，不只给完整案例补值；缺图、撤回和无法评价的范围另报。界限用于显示不确定性，不能消除选择偏差。

### 8.6 停止规则

默认以固定目标招募量为停止依据：达到预定招募身份数，或先达到邀请人数/时间/资源上限时停止；报告实际可分析数与精度。不边看 p 值边追加参与者。若需要补招，只能依据事先定义的退出或技术无效规则，在不查看 D/E 方向的情况下处理，不能因为低评分或“无法判断”对结论不利而补人。

发现技术错误时先暂停，记录影响范围，按预先规则决定是否需要新版本，不能悄悄替换不利结果。

## 9. 自动指标与误差检查怎样辅助研究？

### 9.1 保留识别器，但不让它替人作结论

保留当前 LVFace，正式阶段增加并固定一个不参与该生成器条件或训练的 AdaFace / CurricularFace 系列检查点作为敏感性分析。独立性逐方法记录：不同名字不保证训练数据完全独立；没有审计依据就不声称完全无重叠。

主要报告生成与固定 G 图库的 cosine、目标相对于最近非目标的 margin，以及检测覆盖。真实候选也用同一图库评分。只有另有独立真实校准集时才加入 TAR@FAR；不借用其它论文的阈值，也不在生成测试图上选阈值。

解释方式：

- cosine 变大：该识别空间里更接近；
- margin 变大：相对于其它身份更可分；
- 人评变大：在指定人群与任务中更像；
- 三者可以一致，也可以不一致。

### 9.2 检查“指标能否看出人类变化”

不能只把所有身份、所有方法混在一起算一个相关系数，因为身份本来就有难易差别。至少同时报告：

1. 全部样本的描述性相关；
2. 同一身份内、同一任务或固定对照的变化关系；
3. 本人和陌生人分别计算的关系及不确定性。

若要训练一个由自动指标预测人评的简单模型，只在开发身份上拟合，在确认身份上固定使用。不得用确认人评选择识别器、组合权重或最佳预测层。核心课题不要求训练一个新评价模型。

### 9.3 外观误差只是线索

可以预先限定三类检查：脸部几何比例、表情完成情况、明显皮肤/五官外观变化。自动 landmarks、3D 拟合或分割都有误差，尤其受姿态与光照影响；它们不是人脸形状真值。

只在开发集做少量人工错误描述，避免先看结果后挑一个最显著部位。若正式报告“某个误差解释 likeness”，应有冻结定义、独立测量和相应不确定性；相关关系不能自动升级为因果解释。

复制与跨 seed 多样性用作任务诊断。两 seeds 只能提供粗略的多样性检查，不能据此宣称充分刻画了生成分布。单纯高输入 cosine 也不能证明复制。

## 10. 如果要改进模型，我会怎样决定？

### 10.1 先选一个有理由的干预

| 阶段 C 的观察 | 可考虑的下一步 | 必须有的对照 |
|---|---|---|
| 主要在微笑时变得不像 | 定向补充同身份微笑参考 | 同样图片数量的中性参考与重复参考；评价图库不变 |
| 中性和微笑都差，生成对身份条件反应弱 | 调整合法身份注入强度或时段 | 固定输入、prompt、噪声与模型，检查表情与画质代价 |
| 可重复的几何偏差与 likeness 相关 | 加入适当的几何控制 | 不向干预方法泄露评价目标图；同等输入预算对照 |
| 自动指标很好，人评仍有明确差距 | 检查评价目标与外观误差 | 独立评者、真实参照与固定误差定义 |
| 没有可靠缺口 | 收尾或修正问题定义 | 不继续寻找一个会显著的局部区域 |

这是决策表，不是同时开展四条项目。

### 10.2 最小开发限制

选定一个干预家族后，预先限制为最多三个候选设置，在开发身份上比较。选一个版本冻结后，才使用新的确认身份。

若加入目标表情参考有效，结论首先是“该输入策略有效”，不能自动归因于某个 patch 信息。若改变注入时段有效，结论首先是“该参数在所测配置中影响 likeness”，不能直接说信息原先完整编码或某层擦除了身份。

### 10.3 改善不能靠放弃任务换取

确认改进时，主比较是同身份、同任务的“改进版−原版”人评差。提前设定实际效应要求，并同时要求：

- 任务完成率没有超出预设容许范围的下降；
- 画质没有明显退步；
- 没有通过固定输出或复制输入回避微笑任务。

这些容许范围需要开发测量和样本量支持。“没有显著下降”不等于证明无损；必要时使用非劣效设计，不能仅以 p>0.05 过关。

### 10.4 什么时候才训练 router？

只有外部人评和受控干预共同支持某种信息能改善 likeness，且简单输入或推理参数不能充分解决时，才考虑小模块训练。还必须另有训练身份、验证身份和确认身份，以及独立的算力预算。

当前完成记录不满足这个门槛。**第一版课题不安排新 mapper/router 训练，不承诺论文一定包含新神经网络。**

## 11. 需要多少时间、算力和工程工作？

### 11.1 核心工作量

以下只计算主 likeness 任务，不包括 VAE 检查、练习题、任务完成度、质量评分、退出补招或可选改进。

| 项目 | 开发示例：12 身份、1 模型 | 确认预算示例：40 身份、2 模型 |
|---|---:|---:|
| 生成图：身份 × 模型 × 2 条件 × 2 seeds | 48 | 320 |
| 真实候选：身份 × 2 条件 × 2 张 | 48 | 160 |
| 候选图总数 | 96 | 480 |
| 本人评分：每张由对应本人评分一次 | 96 | 480 |
| 陌生人评分：每张 5 人 | 480 | 2,400 |
| 主评分总数 | 576 | 2,880 |
| 每份 48 题的陌生人表单数 | 10 | 50 |

正式两模型情况下，每位本人只需评自己的 12 张候选，真实照片不因模型数增加而重复展示；分析两模型时会共享真实参照，这种相关性须保留。

40 身份只是预算例子，正式数目必须经功效与资源决策。如果某评分者做多份陌生表单，要保持唯一 ID、避免重复同一候选，并在分析中保留其关联。

### 11.2 算力不是目前最大的瓶颈

历史 PhotoMaker V2 平均约 9.3168 秒/图；48 张按相同吞吐线性估计约 7.5 分钟，40 身份的 PhotoMaker 部分 160 张约 25 分钟。这只是沿用旧配置的纯生成参考时间，不含加载、预处理和重启，也不能用来估算 PuLID / InstantID。

历史峰值显存分配约 6.87 GB、保留约 14.52 GB，已接近 16 GB 卡的保留容量。新模型的速度与显存必须实测。扩散采样参数、精度或 offload 有变化时重新测，不把旧值当保证。[实测记录来源](E:/comp776_3D/reports/GENERATION_IDENTITY_PILOT.md)

假设每次判断 15 秒，开发主评分合计约 2.4 人时，确认主评分约 12 人时；这是所有参与者累计的纯点击时间。实际单题时间、说明时间、招募、退出和支付成本都要由预试验替换估计。

### 11.3 建议时间表：核心课题约八周

这是相对安排，假设所需机构审批或豁免、招募条件已具备；等待审批与无法招募的时间不计入八周承诺。

## 12. 怎样才算完成一个学术课题？

### 12.1 贡献需要比已有文献多一步

F-Bench 已研究自动指标与人类评价的差异；WithAnyone 已研究配对数据与参考复制。因此我们不声称“首次发现识别分数不能代表像本人”。

本课题有机会提供的组合证据是：

1. 同身份真实照片作为经验参照，直接估计生成 likeness 缺口；
2. 分开本人和陌生图库评价，明确两种终点的范围；
3. 在固定的一种表情变化下，比较真实与生成缺口的变化；
4. 在新身份与第二模型上验证，并分析自动指标能否反映变化。

这是**候选贡献定位**。投稿前仍需围绕这一具体组合做一次更新查新，不能仅凭本次阅读宣称首次。

### 12.2 不同结果对应不同论文故事

| 最终结果 | 可以形成的研究 | 不应声称 |
|---|---|---|
| 有稳定缺口，且表情条件缺口扩大 | 有真实参照的生成保真诊断 | 已证明是编码器或去噪某层造成 |
| 人评变化与自动指标持续不一致 | 特定任务与人群下的评价局限 | 所有识别指标都无用 |
| 新干预在独立身份上改善 likeness | 诊断加受控修正 | 改进对所有人、所有生成器普遍有效 |
| 有缺口，但尝试的干预无效 | 诊断研究与受控负结果 | 没有任何方法能解决 |
| 差距小且精度足以排除实际大效应 | 对原始问题范围的修正或负结果 | 模型已经在所有情境都像本人 |
| 区间始终很宽 | 诚实的探索报告与限制 | 已证明不存在差异 |

严谨完成不保证顶会录用。课程/学位层面的完整研究可以是负结果；顶会需要进一步评估新颖性、证据强度与影响。

### 12.3 最终论文结构

1. **引言**：实际问题、为何已有指标不足、我们具体检验什么。
2. **相关工作**：人脸定制生成、身份评价、人类 likeness；说明与现有工作的区别。
3. **方法与协议**：身份划分、照片角色、生成设置、评价者、D/E、冻结分析。
4. **结果**：主终点先报告；其次表情、第二模型、陌生人和自动指标。
5. **诊断或改进**：只有实际开展并有证据的内容才写入。
6. **限制与讨论**：样本、拍摄范围、来源可识别性、缺失、人评主观性、因果边界。
7. **附录与复现**：配置、许可、失败记录、预注册、额外统计与旧探索结果。

E1/E2 可以放在研究动机或附录，解释为什么没有采用“身份层”假设；不必强行让它成为新论文主轴。

### 12.4 完成检查表

- [ ] 主要问题能用两句话说清楚，且不预设答案。
- [ ] 开发与确认身份不重合，设置在确认评分前冻结。
- [ ] 真实候选、评价图库和输入参考角色分离。
- [ ] 本人、熟人、陌生人终点没有混合。
- [ ] 全部预期输出与失败都能追溯。
- [ ] 主结果有身份数、评分数、效应量和不确定性。
- [ ] 不把不显著写成等效，也不把相关写成因果。
- [ ] 任务完成与画质代价被独立报告。
- [ ] 任何未完成或外部未复现的内容清楚标为限制。
- [ ] 别人能按说明复现分析；受限人脸和响应没有被公开。

## 13. 新手怎么学、怎么读论文？

### 13.1 先学足够做实验的知识

**第一层：能理解实验。** 知道图像尺寸、裁切、身份与图像的区别、随机种子、开发集与确认集。

**第二层：能读懂流水线。** 看懂“参考照片 → 编码器 → 身份条件 → 扩散生成 → 评价”的输入输出；理解 checkpoint 是模型参数，config 是运行设置。

**第三层：能判断证据。** 看懂基线、控制变量、消融、区间、泄漏、独立评估器和负结果。

暂时不要求自己完整推导扩散随机微分方程、重写 Transformer，或掌握所有 3D 人脸模型。先能画出本项目的数据流，并指出每一步有没有看到测试身份。

### 13.2 论文阅读顺序

| 顺序 | 阅读材料 | 第一遍只需要回答 |
|---|---|---|
| 1 | [F-Bench / FaceQ](https://arxiv.org/html/2412.13155v1) | 作者如何把 likeness、画质和文本一致性分开？ |
| 2 | [Variability in photos of the same face](https://static1.squarespace.com/static/5e3fac24244c110e4dea7c2a/t/5e43af87685c425c5d5d7c39/1581494168773/JenkinsEtAl2011_Cognition.pdf) | 为什么真实照片也需要多个参照？ |
| 3 | [Not the norm](https://pmc.ncbi.nlm.nih.gov/articles/PMC10161317/) | 熟悉人物的 likeness 为什么不能简化成平均模板距离？ |
| 4 | [Arc2Face](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/05442.pdf) | 哪些证据支持全局向量可用于重建？哪些没有证明？ |
| 5 | [WithAnyone](https://arxiv.org/html/2510.14975v1) | 参考复制与跨条件身份保持有什么区别？ |
| 6 | [Face2Diffusion](https://openaccess.thecvf.com/content/CVPR2024/html/Shiohara_Face2Diffusion_for_Fast_and_Editable_Face_Personalization_CVPR_2024_paper.html) | 表情与身份为什么难同时控制？ |
| 7 | [PhotoMaker 官方实现](https://github.com/TencentARC/PhotoMaker) | 本项目 V2 实际把哪些条件送进了哪里？不要用 V1 论文替代全部 V2 事实 |
| 8 | [PuLID，NeurIPS 2024](https://papers.neurips.cc/paper_files/paper/2024/hash/409fcc9d24b549969b8b9be68b56a7be-Abstract-Conference.html) | 它如何同时考虑身份保持与原模型生成行为？ |

一篇论文先读摘要、主图、实验表和局限，再读方法；不必第一遍读完所有公式。每篇只做一页笔记：

```text
论文解决的问题：
输入与输出是什么：
最关键的一个对照：
结果来自识别器、陌生人，还是本人：
最强证据是什么：
尚不能证明什么：
本项目借鉴哪一步：
```

遇到“我们优于所有方法”，先看它比较了哪些方法、使用什么评价器、输入预算是否一致，以及人评具体问了什么。不要只看示例图。

### 13.3 你与研究助手怎样分工

| 你需要主导 | 研究助手可以承担 | 需要导师或相关审阅者参与 |
|---|---|---|
| 理解并同意研究问题；协调真实参与者；如实记录拍摄与评分情况 | 查论文、实现脚本、构包、校验数据、运行冻结分析、整理图表与草稿 | 课题范围与学术新颖性；机构审批或豁免；同意与数据处理流程；正式统计设计 |

你不需要先成为模型工程师，但必须能说清楚“这张图为什么出现在这个组里”“这条结论具体来自哪个对照”。这是研究判断，不能完全交给自动化。

## 14. 数据、复现与第一周行动

### 14.1 新身份数据的前置条件

按项目约定，在展示可识别照片给评分者前，落实适用的机构审批或豁免。参与者同意须覆盖照片用于生成、生成图和真实图用于评分、谁能访问、保存多久及如何撤回。公开数据集的下载许可不自动等于许可生成或对外展示。

如果暂时无法建立合适的新身份 cohort，可以先完成代码、模拟数据测试和已有许可范围内的工程检查；对 FEI 的进一步探索只能保留受控图库范围，不能替代本人手机人像确认。此时最终产物可降级为探索报告，不能假称已回答“像自己”。

### 14.2 每个新运行必须留下什么？

记录身份分组、照片角色、来源与许可、模型及代码 revision、权重 hash、预处理、prompt、seed、初始 latent hash、输出 hash、失败状态、评分分配、分析版本和性能。保存完整配置、环境锁、源代码快照、日志与完成状态。

不要把“当前 main 分支”当作永久版本；论文复现要知道当时实际用了什么代码。

原始照片、生成图、裁切、embedding、参与者响应与私钥留在 Git 忽略的本地受限目录。新 cohort 的可链接 manifest 也可能是个人数据，应先做去标识与披露检查再决定是否版本化。公开材料优先包括不含个人数据的代码、协议、配置模板、合成测试数据与聚合结果。

### 14.3 第一周只做这五件事

1. **把主问题写到一页纸上。** 默认主终点是 PhotoMaker 的本人真实—生成缺口 D；表情额外缺口 E 是预先规定的次要问题。
2. **与导师确认范围和数据条件。** 先落实能否获得有明确同意的新身份、能否进行本人评分，以及实际期限。
3. **按第 13 节先读前四篇。** 每篇交一页笔记，不急于实现新模型。
4. **准备八张照片的拍摄模板与评分演示。** 用允许使用的独立开发材料演示，不开始正式确认收集。
5. **做工程与分析的假数据检查。** 确认生成矩阵、失败保留、匿名展示和 D/E 方向正确；输出下一步清单与预试验预算。

第一周的成功标志不是“又跑了多少张图”，而是已经有一个别人能看懂、能提出反对意见、也能按规则证伪的实验。

**最终要交付的是一条完整的证据链：我们测到了什么，在什么范围内成立，哪些解释被削弱，哪些仍然未知，以及是否存在经过独立验证的改善。**
